# 초대 링크 유니버설 링크 설정 가이드

앱 쪽 코드·entitlement는 완료됨. 남은 것은 **GitHub 리포 하나 만들고 파일 2개 올리기 + 포털 체크 1개**.
도메인 구입 없이 무료로 동작한다.

## 왜 새 리포가 필요한가

AASA(`apple-app-site-association`)는 **호스트 루트**의
`https://<호스트>/.well-known/apple-app-site-association` 에서 리다이렉트 없이 서비스돼야 한다.
현재 사이트는 프로젝트 페이지(`devk4nt.github.io/flymate-site/`)라서 루트에 파일을 놓을 수 없다.
GitHub Pages의 **유저 사이트**(`devk4nt.github.io` 라는 이름의 리포)만 그 호스트의 루트를 차지한다.
현재 그 리포는 없고 루트는 404다.

루트에 놓인 AASA는 그 호스트의 **모든 경로를 커버**하므로, 랜딩 페이지는 지금 위치
(`/flymate-site/invite.html`)에 그대로 두면 된다. 앱 상수도 바꿀 필요 없다.

## 1. `devk4nt.github.io` 리포 생성 + 파일 2개

리포 이름은 반드시 `devk4nt.github.io` (GitHub 계정명과 일치해야 유저 사이트로 인식됨), Public.

**✅ 2026-09-02 완료됨** — https://github.com/devk4nt/devk4nt.github.io (커밋 `5d6be38`), 로컬은 `~/devk4nt.github.io`.
아래는 재현/이관용 기록.

```bash
cd ~                                 # FlyMate 안에서 실행하면 리포가 중첩 클론된다
gh repo create devk4nt.github.io --public --clone && cd devk4nt.github.io
touch .nojekyll                      # Jekyll이 dot 디렉터리(.well-known)를 기본 제외하므로 필수
mkdir -p .well-known
cp ~/FlyMate/Deliverables/AppStoreConnect/apple-app-site-association .well-known/
git add -A && git commit -m "Add Apple App Site Association for FlyMate universal links"
git push -u origin main              # 첫 푸시는 -u 필요
```

Pages는 유저 사이트라 자동 활성된다. 빌드 완료까지 1~3분 — `gh api repos/devk4nt/devk4nt.github.io/pages -q .status`가
`built`가 될 때까지 기다린 뒤 아래 검증.

## 2. 검증 (앱 제출 **전에** 반드시)

```bash
# ① 파일이 200으로, 리다이렉트 없이 나오는지
curl -i https://devk4nt.github.io/.well-known/apple-app-site-association

# ② Apple CDN이 우리 파일을 JSON으로 제대로 읽었는지 — 여기서 applinks가 보이면 성공
curl -s https://app-site-association.cdn-apple.com/a/v1/devk4nt.github.io | python3 -m json.tool
```

**✅ 2026-09-02 둘 다 통과.** ①은 `http=200 / type=application/octet-stream / redirects=0`,
②는 `http=200`에 `applinks` 정상 파싱 — **GitHub Pages가 Content-Type을 `octet-stream`으로 보내도
Apple CDN은 무시하고 JSON으로 읽는다는 것이 실측 확인됨.** 도메인 구입 불필요.

②가 관문이었다. 여기서 실패하면 GitHub Pages는 응답 헤더를 제어할 수 없어 해결 방법이 없고,
자체 도메인(미등록 확인됨: `flymate.kr`, `flymateapp.com`)이나 헤더 제어가 되는 무료 호스팅
(Cloudflare Pages 등)으로 전환해야 한다. Apple CDN은 최대 24시간 캐시하므로 AASA를 고치면 반영 지연을 감안할 것.

## 3. Apple Developer 포털

Certificates, Identifiers & Profiles → Identifiers → `com.flymate.app`
→ **Associated Domains 체크** → Save.

이 체크 없이 릴리즈 워크플로를 돌리면 프로비저닝 프로파일 발급이 실패한다(entitlement는 이미 커밋됨).
시뮬레이터 빌드는 서명 검증을 안 하므로 로컬 개발에는 영향 없다.

## 4. 시뮬레이터 검증 (스테이징 백엔드)

`FlyMate-Owner` 스킴은 테스트 계정으로 staging Supabase에 실제 로그인한다.
계정 정보는 `mise.local.toml`의 `TUIST_TEST_*`에서 읽고 커밋되지 않는다.

```bash
D=<시뮬레이터 UDID>   # xcrun simctl list devices available
xcodebuild -workspace FlyMate.xcworkspace -scheme FlyMate-Owner -configuration Staging \
  -destination "platform=iOS Simulator,id=$D" -derivedDataPath /tmp/flymate-staging build
xcrun simctl install $D /tmp/flymate-staging/Build/Products/Staging-iphonesimulator/FlyMate.app

eval "$(grep -E '^TUIST_TEST_(PASSWORD|EMAIL_OWNER)' mise.local.toml | sed 's/ *= */=/')"
SIMCTL_CHILD_TEST_EMAIL="$TUIST_TEST_EMAIL_OWNER" \
SIMCTL_CHILD_TEST_PASSWORD="$TUIST_TEST_PASSWORD" \
  xcrun simctl launch $D com.flymate.app
```

**유니버설 링크가 OS 레벨에서 잡히는지 확인** — 대조군을 함께 봐야 의미가 있다.
Safari가 무관한 URL에서는 뜨고 초대 링크에서는 뜨지 않아야 한다:

```bash
front(){ xcrun simctl spawn $D launchctl list | grep -oE "UIKitApplication:(com.apple.mobilesafari|com.flymate.app)" | sort -u; }
xcrun simctl openurl $D "https://example.com";                                   front   # → safari 등장
xcrun simctl terminate $D com.apple.mobilesafari
xcrun simctl openurl $D "https://devk4nt.github.io/flymate-site/invite.html?code=WF852C"; front
# → safari 없이 flymate만 있으면 AASA 라우팅 성공
```

⚠️ `xcodebuild -only-testing:` 는 **필터가 아무것도 매칭하지 않아도 TEST SUCCEEDED를 반환**한다.
새 테스트 파일을 추가한 뒤에는 `tuist generate`로 타겟에 반영하고,
`Test Case ... started` 로그가 실제로 찍히는지 확인할 것.

## 5. 실기기 검증

문자(iMessage)로 `https://devk4nt.github.io/flymate-site/invite.html?code=ABC123` 을 보내 탭 →
앱이 바로 열려야 한다. Safari 주소창에 직접 입력하면 유니버설 링크가 동작하지 않는 것이 정상(링크 탭만 동작).
개발 중 CDN 캐시를 우회하려면 기기 설정 → 개발자 → Associated Domains Development 활성화.

⚠️ **카카오톡은 링크를 자체 인앱 브라우저로 열기 때문에 유니버설 링크 핸드오프가 걸리지 않는 것이 일반적이다.**
카톡으로 받은 사람은 랜딩 페이지를 보고 "앱에서 가입 신청하기"를 한 번 더 눌러야 한다 —
그래서 `invite.html`은 유니버설 링크를 붙인 뒤에도 계속 필요하다. 실기기로 실제 동작을 확인할 것.

## 나중에 자체 도메인으로 옮길 때

바꿀 곳 3군데뿐이다. 초대 링크는 일회성이라 옛 링크가 깨져도 실질 피해가 없다.

1. `AppConstants.ServiceURL.inviteLanding` — 이 상수 하나가 공유 링크 생성과 유니버설 링크 파싱의
   유일한 출처다 (`DeepLinkParser.inviteShareURL` / `parse`). `DeepLinkParserTests`의 하드코딩된
   기대 URL 2개도 함께 수정
2. `FlyMate/FlyMate.entitlements` 의 `applinks:` 값
3. AASA의 `"/"` 경로 — 커스텀 도메인을 붙이면 사이트가 루트로 옮겨가므로 `/invite.html`
